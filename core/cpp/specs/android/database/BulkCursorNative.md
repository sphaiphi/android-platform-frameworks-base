# BulkCursorNative - Reverse Engineering Documentation

## Executive Summary
`BulkCursorNative` is the native (Stub) implementation of the `IBulkCursor` binder interface. It handles incoming IPC transactions, unmarshals arguments, and dispatches calls to the abstract methods (implemented by subclasses like `CursorToBulkCursorAdaptor`). It also includes the `BulkCursorProxy` inner class for the client side.

## Architecture Overview
*   **Inheritance**: `Binder` -> `BulkCursorNative` -> `IBulkCursor`.
*   **Role**: Server-side Binder stub.

## Detailed Functionality
*   **onTransact**:
    *   Switches on transaction code.
    *   Unparcels arguments (e.g., `startPos` for `getWindow`).
    *   Calls implementation (e.g., `getWindow(startPos)`).
    *   Parcels result (e.g., writes the `CursorWindow` to the reply parcel).
*   **asInterface**: Standard Binder helper to get proxy or local implementation.

## C++ Implementation Guidance
*   **Base Class**: `BnBulkCursor` (generated by AIDL).
*   **Manual vs Generated**: The Java code manually implements `onTransact`. In modern C++, prefer AIDL generation, but if manual implementation is needed, replicate the parcel reading/writing order exactly.

## Data Model
*   **Transactions**:
    *   `GET_CURSOR_WINDOW`: Reads int (pos), writes window (if not null).
    *   `DEACTIVATE`: Void.
    *   `CLOSE`: Void.
    *   `REQUERY`: Reads observer, writes int (count) + bundle.
    *   `ON_MOVE`: Reads int.
    *   `GET_EXTRAS`: Writes bundle.
    *   `RESPOND`: Reads bundle, writes bundle.
