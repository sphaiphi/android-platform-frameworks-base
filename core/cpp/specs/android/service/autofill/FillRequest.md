# FillRequest - Reverse Engineering Documentation

## Executive Summary
`FillRequest` carries the data required for an `AutofillService` to fulfill a request. It primarily contains the `AssistStructure` (view hierarchy) via `FillContext`s and any `ClientState` from previous requests.

## Data Model

### Fields
*   `mId`: `int` - Unique request ID.
*   `mFillContexts`: `List<FillContext>` - Snapshot(s) of the screen. List because it might include previous contexts if `FLAG_DELAY_SAVE` was used.
*   `mHints`: `List<String>` - Type hints (e.g., "username") if platform detection is enabled.
*   `mClientState`: `Bundle` - State passed back and forth between service and system.
*   `mFlags`: `int` - Bitmask (e.g., `FLAG_MANUAL_REQUEST`).
*   `mInlineSuggestionsRequest`: `InlineSuggestionsRequest` - Specs for inline suggestions (max count, size) if supported.
*   `mDelayedFillIntentSender`: `IntentSender` - To support sending a response later.

### Flags
*   `FLAG_MANUAL_REQUEST`: User forced autofill.
*   `FLAG_COMPATIBILITY_MODE_REQUEST`: Request via accessibility bridge.
*   `FLAG_PASSWORD_INPUT_TYPE`: Password field involved.

## Java-to-C++ Translation Guide

### Parcelable
*   **Java**: Generated by `DataClass`.
*   **C++**: `android::Parcelable`.
    *   `mFillContexts` is a list of Parcelables.
    *   `mClientState` is a Bundle.

### Dependencies
*   `FillContext` (wraps `AssistStructure`).
*   `InlineSuggestionsRequest`.

## Implementation Notes
*   **Immutable**: Created by system, consumed by service.
*   **Contexts**: Accessing the view hierarchy requires iterating through `FillContext`.
