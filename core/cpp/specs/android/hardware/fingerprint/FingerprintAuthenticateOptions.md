# FingerprintAuthenticateOptions - Reverse Engineering Documentation

## Executive Summary
`FingerprintAuthenticateOptions` is a configuration class used to specify parameters when requesting fingerprint authentication or detection. It implements `AuthenticateOptions` and `Parcelable`.

## Architecture Overview
- **Type**: Data Class / Parcelable.
- **Implements**: `android.hardware.biometrics.AuthenticateOptions`, `android.os.Parcelable`.
- **Generation**: Uses `com.android.internal.util.DataClass` annotation to generate boilerplate code.

## Detailed Functionality

### Fields
- `mUserId` (`int`): User ID for the operation. Default: 0.
- `mSensorId` (`int`): Sensor ID. Default: `SENSOR_ID_ANY`.
- `mIgnoreEnrollmentState` (`boolean`): Whether to ignore enrollment state checks. Default: `false`.
- `mDisplayState` (`int`): Current display state. Uses `AuthenticateOptions.DisplayState`. Default: `DISPLAY_STATE_UNKNOWN`.
- `mOpPackageName` (`String`): Calling package name. Default: "" (empty string).
- `mAttributionTag` (`String`): Attribution tag. Default: null.
- `mVendorReason` (`AuthenticateReason.Vendor`): Custom vendor reason. Default: null.
- `mIsMandatoryBiometrics` (`boolean`): Mandatory biometrics flag.

## Data Model
- **Primitive types**: `int`, `boolean`.
- **String types**: `String`.
- **Custom types**: `AuthenticateReason.Vendor`.

## Implementation Risks
- **Parceling Logic**: Matches bitmask logic (`flg`) generated by `DataClass`.
    - `mIgnoreEnrollmentState`: `flg |= 0x4`
    - `mIsMandatoryBiometrics`: `flg |= 0x80`
    - `mAttributionTag`: `flg |= 0x20`
    - `mVendorReason`: `flg |= 0x40`
