# AudioPlaybackHandler - Reverse Engineering Documentation

## Executive Summary
`AudioPlaybackHandler` manages a dedicated thread for playing back audio generated by the TTS engine. it maintains a queue of `PlaybackQueueItem` objects and processes them sequentially.

## Architecture Overview

### Threading Model
- **Worker Thread**: `mHandlerThread` ("TTS.AudioPlaybackThread").
- **Queue**: `mQueue` (`LinkedBlockingQueue<PlaybackQueueItem>`). Unbounded.
- **Message Loop**: An internal `Runnable` that takes items from the queue and calls their `run()` method.

## Detailed Functionality

### Queue Management
- `enqueue(PlaybackQueueItem)`: Adds an item to the queue.
- `stopForApp(Object callerIdentity)`: Removes all items from the queue belonging to a specific caller and stops the currently playing item if it belongs to that caller.
- `stop()`: Clears the queue and stops the current item.
- `quit()`: Shuts down the thread and clears everything.

### Status
- `isSpeaking()`: Returns true if the queue is not empty or an item is currently being processed.

## Java-to-C++ Translation Guide

### Implementation
- Use a worker thread (`std::thread` or `jthread`).
- Use `std::deque` with a `std::mutex` and `std::condition_variable` to implement the blocking queue.
- Ensure `PlaybackQueueItem::stop()` is thread-safe as it can be called from the control thread while `run()` is executing on the playback thread.
