# DisplayHashingService - Reverse Engineering Documentation

## Executive Summary
`DisplayHashingService` is an abstract base class for services that generate and verify cryptographically secure hashes of display content. It allows the system to validate that specific content was indeed rendered on the screen, providing a mechanism for non-repudiation of UI display.

## Architecture Overview
*   **Inheritance**: Extends `android.app.Service`.
*   **IPC**: Implements `IDisplayHashingService.Stub` (internal wrapper).
*   **Threading**: Uses a `Handler` on the main looper to marshal binder calls to service methods.
*   **Rate Limiting**: Includes a mechanism to specify a mandatory interval between hashing requests to prevent abuse or performance degradation.

## Detailed Functionality

### `onBind(Intent intent)`
**Purpose**: Returns the `IDisplayHashingService` binder interface.

### Core Abstract Methods
*   **`onGenerateDisplayHash(byte[] salt, HardwareBuffer buffer, Rect bounds, String hashAlgorithm, DisplayHashResultCallback callback)`**:
    *   **Goal**: Create a secure hash of the provided `HardwareBuffer` (which contains the raw pixels of the display area).
    *   **Salt**: The salt should be unique to the caller to prevent other processes from verifying the hash.
    *   **Bounds**: The area within the buffer to be hashed.
*   **`onVerifyDisplayHash(byte[] salt, DisplayHash displayHash)`**:
    *   **Goal**: Validate a previously generated `DisplayHash`.
    *   **Returns**: A `VerifiedDisplayHash` if valid, or `null` if the hash is invalid or was not generated by this system with the given salt.
*   **`onGetDisplayHashAlgorithms()`**:
    *   **Goal**: Provide a list of supported hashing algorithms (e.g., "HMAC-SHA256").
*   **`onGetIntervalBetweenRequestsMillis()`**:
    *   **Goal**: Define the throttling interval for hashing requests.

### IPC Dispatches
*   **`generateDisplayHash`**: Dispatches to `onGenerateDisplayHash`. Wraps the result or error into a `Bundle` sent via `RemoteCallback`.
*   **`verifyDisplayHash`**: Dispatches to `onVerifyDisplayHash`. Sends the `VerifiedDisplayHash` result via `RemoteCallback`.
*   **`getDisplayHashAlgorithms`**: Dispatches to `onGetDisplayHashAlgorithms`.
*   **`getIntervalBetweenRequestsMillis`**: Dispatches to `onGetIntervalBetweenRequestsMillis`.

## Java-to-C++ Translation Guide

### Data Structures
*   `HardwareBuffer` maps to `AHardwareBuffer` in NDK.
*   `DisplayHash` and `VerifiedDisplayHash` are Parcelables.
*   `RemoteCallback` is used for asynchronous results back to the system server.

### Security
*   The implementation should use strong cryptographic primitives (e.g., HMAC with SHA-256) for generating the hash.
*   The salt must be handled securely.

## Implementation Risks
*   **Performance**: Hashing raw pixel buffers can be expensive. Implementations might use hardware acceleration (e.g., DSP or GPU) if available.
*   **Privacy**: Access to raw pixel buffers is highly sensitive. The service must ensure that buffers are only accessed for the purpose of hashing and are not leaked or stored.
