# InputEventConsistencyVerifier - Reverse Engineering Documentation

## Executive Summary
`InputEventConsistencyVerifier` is a diagnostic utility used to detect logical errors in input event streams (e.g., a "Key Up" without a "Key Down"). It monitors the state of keys, touch pointers, and buttons to ensure that the events delivered to or generated by a component are consistent with the system's input protocols.

## Architecture Overview
*   **Role**: Input pipeline debugger.
*   **Availability**: Active primarily on `eng` or `debug` builds.
*   **Scope**: Tracks state for Keys, Trackballs, Touch, and Generic Motion events.

## Detailed Functionality

### 1. Key Consistency
*   Ensures `ACTION_DOWN` is followed by `ACTION_UP`.
*   Checks that `ACTION_DOWN` doesn't occur for an already-pressed key (unless it's a repeat).

### 2. Touch Consistency
*   Validates that pointer IDs in `ACTION_POINTER_DOWN` / `UP` are consistent.
*   Ensures `ACTION_DOWN` only happens when no other pointers are already down.
*   Checks that `ACTION_MOVE` has the expected number of pointers.

### 3. Tainting
*   When a violation is detected, it logs a detailed message and marks the event as "tainted" using `FLAG_TAINTED` to prevent duplicate error reports.

## Java-to-C++ Translation Guide
*   **Logging**: Use `ALOGD` or equivalent for violation reports.
*   **State**: Uses a `KeyState` linked list and a bitfield (`mTouchEventStreamPointers`) for pointer tracking.

## Implementation Risks
*   **False Positives**: Custom components that deliberately manipulate event streams (like custom gesture detectors) may trigger consistency violations if they don't follow the system's exact state rules.
