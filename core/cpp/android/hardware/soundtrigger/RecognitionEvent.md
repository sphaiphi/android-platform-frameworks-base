# RecognitionEvent - Reverse Engineering Documentation

## Executive Summary
`RecognitionEvent` represents the notification sent by the `SoundTrigger` system when a sound pattern is detected or when an error occurs during active listening. It contains the detection status, the originating model handle, and metadata for transitioning to audio capture.

## Architecture Overview
- **Hierarchy**: Base class for `KeyphraseRecognitionEvent` and `GenericRecognitionEvent`.
- **Transmission**: Delivered asynchronously via `StatusListener.onRecognition`.
- **Payload**: Includes audio session info, capture parameters, and vendor-specific results.

## Detailed Functionality

### Status Reporting
**Purpose**: To indicate the outcome of the recognition attempt.
**Codes**:
- `RECOGNITION_STATUS_SUCCESS`: Pattern matched.
- `RECOGNITION_STATUS_ABORT`: Recognition cancelled by the system.
- `RECOGNITION_STATUS_FAILURE`: Processing error in the DSP.

### Capture Transition
**Purpose**: To allow seamless handover to an `AudioRecord` instance.
**Mechanism**:
- `captureAvailable`: If true, the DSP has buffered the audio that triggered the event.
- `captureSession`: The audio session ID to use when opening the microphone.
- `captureDelayMs`: Offset between detection and audio availability.

### Data Synchronization
**Java-Specific Notes**: Includes `halEventReceivedMillis`, which uses `SystemClock.elapsedRealtime()` to record exactly when the HAL fired the event, allowing for accurate latency measurements.

## Data Model

### Members
- `status` (`int`): Result code.
- `soundModelHandle` (`int`): ID of the loaded model.
- `captureFormat` (`AudioFormat`): The format of the buffered audio.
- `data` (`byte[]`): Opaque vendor results (e.g., confidence scores).

## API Reference

### Public Methods
- `boolean isCaptureAvailable()`
- `AudioFormat getCaptureFormat()`
- `int getCaptureSession()`
- `byte[] getData()`
- `long getHalEventReceivedMillis()`

## Java-to-C++ Translation Guide

### Audio Format
- **Java**: `android.media.AudioFormat`.
- **C++**: Use `audio_format_t`, `audio_channel_mask_t`, and sample rate integers from `system/audio.h`.

### Event Dispatch
- **Java**: Marshalled from `RecognitionEventSys` AIDL structure.
- **C++**: The C++ listener will receive a `RecognitionEvent` struct directly from the `ISoundTriggerCallback` binder.

## Test Cases & Validation
1. **Status Mapping**: Verify that each `RECOGNITION_STATUS_*` code maps correctly from the HAL to the public API.
2. **Audio Session Propagation**: Ensure the `captureSession` ID passed to the app matches the one generated by the audio policy manager.
3. **Preamble Length**: Verify that `capturePreambleMs` correctly describes the amount of audio buffered *before* the trigger point.
