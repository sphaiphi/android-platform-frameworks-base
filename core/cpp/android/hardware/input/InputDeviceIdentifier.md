# InputDeviceIdentifier - Reverse Engineering Documentation

## Executive Summary
`InputDeviceIdentifier` uniquely identifies an input device using its descriptor, vendor ID, and product ID. It is used to persist settings for specific devices (like keyboard layouts).

## Architecture Overview
- **Parcelable**: Transmissible across IPC.
- **Immutable**: Fields are final.

## Detailed Functionality

### Identification
**Purpose**: unique key for input devices.
**Fields**:
- `mDescriptor`: String (unique string generated by kernel/inputflinger).
- `mVendorId`: int (USB Vendor ID).
- `mProductId`: int (USB Product ID).

## Data Model
- `String descriptor`
- `int vendorId`
- `int productId`

## API Reference
- `String getDescriptor()`
- `int getVendorId()`
- `int getProductId()`
- `equals/hashCode`: Based on all three fields.

## Java-to-C++ Translation Guide
- **Struct**: `struct InputDeviceIdentifier { std::string descriptor; int32_t vendorId; int32_t productId; };`
- **Serialization**: Standard Parcel read/write.

## Test Cases & Validation
- Equality checks: Two objects with same values must be equal.
- Parceling: Write to parcel and read back, fields must match.

## Implementation Risks
- `descriptor` string encoding (UTF-8/16) handling between Java/C++.
