# ContentProviderNative - Reverse Engineering Documentation

## Executive Summary
`ContentProviderNative` is the Binder stub (`Bn`) implementation for `IContentProvider`. It handles incoming Binder transactions and dispatches them to the abstract methods (implemented by `ContentProvider.Transport`). It also includes the `ContentProviderProxy` (client side).

## Architecture Overview
- **Inheritance:** Extends `Binder`, Implements `IContentProvider`.
- **Pattern:** standard AIDL-style Stub/Proxy.

## Detailed Functionality

### `onTransact(int code, Parcel data, Parcel reply, int flags)`
**Purpose**: Marshals/unmarshals data for IPC calls.
**Algorithm**: Switch case on transaction codes (`QUERY_TRANSACTION`, `INSERT_TRANSACTION`, etc.). Reads arguments from `data` Parcel, calls implementation, writes result to `reply` Parcel.

### `asInterface(IBinder obj)`
**Purpose**: Factory to get `IContentProvider`. Returns `this` if local, or creates `ContentProviderProxy`.

### `ContentProviderProxy` (Inner Class)
**Purpose**: The client-side proxy (`BpContentProvider`).
**Algorithm**: Marshals arguments into a Parcel and calls `mRemote.transact`. Handles `BulkCursor` specifically for queries.

## Data Model
- `descriptor`: String "android.content.IContentProvider".

## API Reference
- `public static IContentProvider asInterface(IBinder obj)`
- `public abstract String getProviderName()`

## Java-to-C++ Translation Guide
- **AIDL**: This class is essentially manual AIDL code. In modern Android C++, this is generated by the AIDL compiler (`IContentProvider.aidl`). C++ should use the generated `BnContentProvider` and `BpContentProvider`.
- **BulkCursor**: The special handling of `Cursor` returning `BulkCursorDescriptor` needs to be matched in C++.

## Implementation Risks
- **Parcel Format**: The exact order of writing/reading fields in `Parcel` MUST match the C++ implementation.
