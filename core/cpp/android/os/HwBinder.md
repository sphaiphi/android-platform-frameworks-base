# HwBinder - Reverse Engineering Documentation

## Executive Summary
`HwBinder` is the Java counterpart to the native `hardware::BHwBinder`. It implements the `IHwBinder` interface and serves as the local endpoint for HIDL (Hardware Interface Definition Language) IPC. It allows Java services to be registered with the `hwservicemanager` and handle incoming transactions.

## Architecture Overview
-   **Role**: HIDL Stub / Local Object.
-   **Native Peer**: `android_os_HwBinder.cpp` links this to `libhwbinder`.
-   **Interface**: `IHwBinder`.
-   **Service Registration**: `registerService(String serviceName)` calls native `registerService`, publishing the object to `hwservicemanager`.

## Detailed Functionality
-   **`onTransact`**: Abstract method called by the native `JHwBinder::onTransact` when a request arrives. Subclasses (generated by `hidl-gen`) implement this to dispatch methods.
-   **`getService`**: Static helper to retrieve a remote interface (returns `HwRemoteBinder` wrapped in a proxy).
-   **`configureRpcThreadpool` / `joinRpcThreadpool`**: Manages the thread pool for HIDL binder threads (separate from the framework Binder thread pool).

## Java-to-C++ Translation Guide
-   **Equivalent**: `hardware::BHwBinder`.
-   **Relationship**: This class *is* the Java wrapper for the C++ `BHwBinder`.
-   **Difference from `Binder`**: `HwBinder` is strictly for HIDL (HALs), while `Binder` is for AIDL (Framework). They use different drivers (`/dev/hwbinder` vs `/dev/binder`) and context managers.

## Implementation Risks
-   **Thread Management**: HIDL requires explicit thread pool configuration (`configureRpcThreadpool`). Failing to do so might lead to single-threaded dispatch or starvation.
