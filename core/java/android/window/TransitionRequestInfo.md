# TransitionRequestInfo - Reverse Engineering Documentation

## Executive Summary
`TransitionRequestInfo` is sent from the `WindowManagerService` to a `TransitionPlayer` (like the Shell) to request the initiation of a new transition. it describes the trigger event (e.g., an activity starting) and provides initial hints about what might be involved.

## Architecture Overview
*   **Package**: `android.window`
*   **Type**: `final class` implements `Parcelable`
*   **Role**: Transition trigger notification.
*   **Inner Classes**: `DisplayChange`, `PipChange`.

## Data Model

| Field | Type | Description |
| :--- | :--- | :--- |
| `mType` | `int` | Transition type (OPEN, CLOSE, etc.). |
| `mTriggerTask` | `RunningTaskInfo` | The task that triggered the transition. |
| `mPipChange` | `PipChange` | Metadata if this is a PiP transition. |
| `mRemoteTransition` | `RemoteTransition` | (Optional) Transition provided by the caller. |
| `mDisplayChange` | `DisplayChange` | Metadata if display properties changed. |
| `mFlags` | `int` | Initial transition flags. |

## Detailed Functionality

### `DisplayChange`
Captures `mDisplayId`, start/end bounds, start/end rotation, and physical display changes.

### `PipChange`
Captures the `TaskFragment` token and `TaskInfo` for the PiP candidate.
