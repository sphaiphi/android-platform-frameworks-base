# Implementation Plan: WindowManager

**Branch**: `001-window-manager` | **Date**: 2026-05-10 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-window-manager/spec.md`

## Summary

Implement the `WindowManager` class — the primary API for adding, updating, and removing views from windows. The implementation follows the Android framework pattern of `WindowManagerImpl` delegating to a singleton `WindowManagerGlobal`, with each added view managed via its own `ViewRootImpl` instance. This bridges the existing View/ViewGroup rendering system to the Window/IWindowSession infrastructure.

## Technical Context

**Language/Version**: C++23 (per project constitution)
**Primary Dependencies**:
- `View`, `ViewGroup` (core view hierarchy)

- `WindowManager` (existing header stub)
**Storage**: N/A (in-memory only)
**Testing**: GoogleTest (gtest) + GoogleMock (gmock) via CMake host build; CTS for on-device validation
**Target Platform**: Host build (Linux, CMake + gtest); On-device (Android NDK r29, ndk-build)
**Project Type**: Native framework library (NDK)
**Performance Goals**: Layout updates within one display refresh cycle (16.67ms at 60Hz); zero-copy view management via smart pointers
**Constraints**: Must mirror Java WindowManager API surface; no JNI; C++23 only; uses mock binder headers on host builds (define `HOST_BUILD`)
**Scale/Scope**: 2-3 source files (WindowManager.h, WindowManagerGlobal.h, WindowManagerImpl.h/cpp), ~500-800 lines total

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

### Principle I: Safety-First Design
- **Compliant**: ViewRootImpl tracking uses `std::shared_ptr<View>` and `std::unique_ptr<ViewRootImpl>`. No raw pointers for owned objects.
- **Compliant**: LayoutParams passed by `std::shared_ptr`, no raw pointer exposure.

### Principle II: Zero-Cost Abstractions
- **Compliant**: WindowManagerImpl is a thin delegator to WindowManagerGlobal (one function call per operation). No virtual dispatch on the hot path.
- **Compliant**: WindowManagerGlobal uses flat containers (`std::vector`) for O(n) but minimal overhead iteration.

### Principle III: Test-Driven Development
- **Compliant**: Unit tests will be written before implementation (Red-Green-Refactor).
- **Compliant**: CTS validation planned for compliance.
